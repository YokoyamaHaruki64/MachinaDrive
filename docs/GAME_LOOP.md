# Wave Survival ゲーム設計

## 目的

プレイヤーは制限時間が尽きる前に、出現する敵をすべて倒して次のWaveへ進む。HPではなく残り時間を生存リソースとし、敵の撃破とWaveクリアによって時間を回復する。短い判断と連続撃破を気持ちよく感じられる、少数Waveのアリーナアクションを最初のPlayable目標とする。

本資料はゲーム固有のルールと実装分担を扱う。エンジンのScene、Prefab、描画、Audio、PostProcessの利用方法は [GAME_DEVELOPMENT.md](GAME_DEVELOPMENT.md) と [RENDERING.md](RENDERING.md) を正とする。

## 最小Playable仕様

| 要素 | 初期仕様 |
| --- | --- |
| 開始時間 | 60秒 |
| 時間減少 | 常時、毎秒1秒 |
| 敗北 | 残り時間が0秒になった時点 |
| 敵撃破 | 時間回復アイテムを1個落とす |
| 回復アイテム | 接触または近距離取得で残り時間を回復する |
| Waveクリア | 残敵数が0になった後、時間を回復して次Waveへ移る |
| Wave数 | 上限なし。Waveをクリアする限り次Waveを開始する |
| 表示 | 残り時間、Wave番号、残敵数、コンボ |

初期値はバランス調整用であり、ゲーム進行を保持するScriptのInspectorフィールドとして公開する。回復によって残り時間が最大値を超えないようにする。

## 進行状態

```text
GameStart
  ↓
WaveIntro（開始前インターバル）
  ↓
Combat ── 残敵数0 ──→ WaveClear（タイマー停止・PlayerがIdleになるまで待機）
  ↑                         │
  │                         ├─ PlayerがIdle → 時間回復 → 数秒待機 → WaveIntro
  │                         └─ 最終Wave   → Result
  │
  └─ 時間回復アイテムを取得

任意の状態 ── 残り時間0 ──→ TimeUp → Result
```

`WaveDirector` が上記状態、現在Wave、残り時間、敵の生成を一元管理する。`Enemy`、回復アイテム、HUDは進行状態を直接変更せず、Directorの公開APIを通じて通知する。これにより、敵の種類や回復方式を増やしてもゲームルールを分散させない。

最終Waveは設けない。`Result`へ進む契機はTimeUpのみとし、到達Waveを結果として表示できるようにする。Combat以外の状態では残り時間を減らさず、次Waveの生成完了と同時に時間減少を再開する。Waveクリア後の回復はPlayerがIdleかつヒットストップ解除済みになった時点で行う。

## Scriptの責務

| Script | 責務 |
| --- | --- |
| `WaveDirector`（新規） | 時間減少、Wave構成、出現矩形内での敵生成、残敵確認、Waveクリア／TimeUp、HUD更新 |
| `Enemy`（拡張） | 死亡時にDirectorへ撃破通知し、回復アイテムPrefabを生成する |
| `TimePickup`（新規） | 接触判定、取得時の時間回復、取得演出、自己破棄 |
| `GameHud`（拡張） | 既存のゲージを残り時間として表示し、Wave番号と残敵数をDirectorから表示する |
| `TutorialController`（新規） | 最初のプレイ中だけ、移動・攻撃・時間回復の順に短い説明を表示する |

`Enemy::OnDestroy()`で残敵数を直接数え直す現在の処理は、Wave制導入時に`WaveDirector`へ集約する。これにより、画面外の敵、破棄予約中の敵、次Waveの生成タイミングに表示が引きずられないようにする。

## 無限Waveと敵生成

### 出現矩形

Fieldには次の空GameObjectを置き、対応するTagを設定する。`WaveDirector`はそのWorld PositionのXZ値から出現矩形を求める。マーカーは描画・物理判定を持たない設定用Objectとする。

| GameObject名 | Tag | 用途 |
| --- | --- | --- |
| `Field_LeftUp` | `EnemySpawnArea` | X最小、Z最大の角 |
| `Field_RightUp` | `EnemySpawnArea` | X最大、Z最大の角 |
| `Field_LeftBottom` | `EnemySpawnArea` | X最小、Z最小の角 |
| `Field_RightBottom` | `EnemySpawnArea` | X最大、Z最小の角 |

`WaveDirector`は`EnemySpawnArea`タグを持つ4点すべてを走査して`minX`、`maxX`、`minZ`、`maxZ`を求め、XとZをそれぞれ独立した一様分布で選ぶ。これにより、矩形内の各面積が同じ確率で選ばれる。単に四隅をランダム補間する方式は、実装によっては中央または角へ偏るため用いない。

初回実装ではプレイヤーからの最小距離を設定し、条件を満たすまで最大回数だけ再抽選する。上限回数を超えた場合は、矩形中心から最も離れた有効候補を使う。敵同士の重なり回避は、必要になった時点でPhysicsのOverlap判定または占有半径を追加する。

### Wave式と上限

Wave番号を`w`（1以上）とする。以下の係数と上限は、すべて`WaveDirector`のInspector設定にする。

| 値 | 初期式 | 意図 |
| --- | --- | --- |
| 出現数 `N(w)` | `min(maxEnemyCount, baseEnemyCount + floor(enemyCountGrowth * pow(w - 1, enemyCountExponent)))` | 終盤ほど増加を強めつつ、画面とCPUを守る |
| Waveクリア回復 `C(w)` | `min(maxClearTimeBonus, baseClearTimeBonus + clearTimeGrowth * sqrt(w - 1))` | 後半の回復が増え過ぎないようにする |
| Moving確率 `Pmove(w)` | `clamp(movingStart + movingGrowth * (w - 1), 0, movingMax)` | Waveごとに位置取りを要求する |
| Heavy確率 `Pheavy(w)` | `clamp(heavyGrowth * max(0, w - heavyStartWave), 0, heavyMax)` | 序盤では出さず、徐々に重い敵を混ぜる |
| Basic確率 `Pbasic(w)` | `max(0, 1 - Pmove(w) - Pheavy(w))` | 残りの確率をBasicへ割り当てる |

敵種は1体ごとに一様乱数を取り、`Pbasic`、`Pmove`、`Pheavy`の累積確率で選ぶ。`Pmove + Pheavy`が1を超える設定はInspectorで警告し、実行時は正規化して安全に扱う。撃破時の回復は初期値を+4秒とし、ドロップ確率、最大時間、Wave間待機時間もInspectorで調整可能にする。

`enemyCountExponent` は1.0以上を設定する。初期値の1.25では終盤ほど敵数の増加を強める。敵数上限とクリア回復上限は必須である。上限到達後は敵数・回復量が一定になり、上手いプレイなら理論上継続できる。時間切れをより起こしやすくする必要が出た場合は、敵HP、射撃頻度、時間減少速度のいずれかをWaveに応じて増加させる。ただし、上限のある要素だけではTimeUpを数学的に保証できないため、無限Waveの目的を「記録を伸ばせるサバイバル」とするか、別途ハードリミットを設けるかをプレイテスト後に決める。

## HUDとフィードバック

- 既存HUDは時間制の情報優先度に合わせて作り直す。数値を主表示、ゲージを補助表示とする。
- 残り時間は常時 `TIME 060.00` の形式で表示する。整数部は3桁、少数部は2桁でゼロ埋めし、開始時間が60秒なら `060.00` とする。上限は999.99秒とし、表示前にClampする。
- `TIME` ラベルは小さく、数値を大きく表示する。横長の残量バーは数値の下または横に薄く配置し、時間の大まかな残量を補助する。
- 表示文字は数字スプライトを個別に並べず、Bitmapフォントを用いて `TIME`、整数部、小数点、少数部を一貫した字形で描画する。
- 残り時間が閾値（例: 15秒）以下では、ゲージ色を警告色にし、点滅または短い画面演出を加える。
- 敵撃破時は、残敵数の更新、コンボ加算、敵爆発、回復アイテムの出現を同フレームまたは直後に行う。
- 回復アイテム取得時は、TIMEゲージ増加、`+4.00` の数値ポップ、明るいSE、粒子を同時に出す。
- Wave開始時は `WAVE 1`、Waveクリア時は `CLEAR +12s` のように短く表示する。操作を妨げる長い停止演出は使わない。

### UIシェーダー方針

Bitmapフォントでも、各文字のUVを使うUIシェーダーで次の装飾を行える。文字列の正確さはフォントデータで担保し、装飾はMaterial Property Overrideから動的に制御する。

- 文字のローカル座標またはUVに基づく上下・斜めグラデーション
- アルファ境界を使う細い輪郭線
- 高輝度の発光色と既存Bloomを組み合わせた光彩
- 残り15秒以下の警告色、点滅、軽い色シフト
- 時間回復時の短い明滅、発光強度の増加

フォントアトラス上で隣接する文字を光彩が拾わないよう、初回は細い輪郭線とBloom中心で実装する。広い光彩や距離場ベースの滑らかな縁取りが必要になった場合は、SDFフォントの導入を別途検討する。

## VFX・ポストプロセス・サウンド

### VFX

既存の `Explosion.prefab`、`Trail`、`ParticleSystem` を優先して使う。最小版では次の4種類を作る。

| 契機 | 表現 | 実装候補 |
| --- | --- | --- |
| 攻撃命中 | 短い閃光と火花 | ParticleSystem、既存particleテクスチャ |
| 敵撃破 | 爆発・破片・リング | Explosion.prefab、ParticleSystem |
| 回復アイテム | 上昇粒子、プレイヤーへの吸引Trail | ParticleSystem、Trail |
| 時間切れ間近 | 小さな画面ノイズまたはゲージ発光 | UI Material、PostProcess |

Trailには細い発光テクスチャ、ParticleSystemには加算合成に向いた白地の円形・ノイズ・放射状テクスチャを使う。色・寿命・速度・サイズはテクスチャへ焼き込まず、MaterialとParticleSystemの設定で変えられるようにする。

### ポストプロセス

既存のBloomを常時有効にし、発光する弾・回復アイテム・UIを読みやすくする。初回の追加ポスプロは、時間切れ間近だけに使う軽量な色調変化またはVignette相当の1Passに限定する。画面全体の激しい揺れ・常時ノイズは、視認性と作業時間の観点から後回しにする。

### サウンド

最低限、BGM、攻撃／命中、敵撃破、回復取得、Wave開始・クリア、TimeUpを用意する。各SEは音量とピッチをInspectorで調整できるようにし、短い音はPrefabまたは専用Audio GameObjectから再生する。現時点で確認できるローカル音源は `bgm.wav` と `wan.wav` のみなので、効果音の種類を増やすには追加素材が必要である。

## チュートリアル

初回のGame開始後に、以下を画面端へ順に表示する。入力停止は行わず、条件を満たしたら次へ進む。

1. 「移動して敵へ近づこう」
2. 「攻撃で敵を倒そう」
3. 「敵が落とす時間を取って延長しよう」
4. 「敵を全滅させて次のWaveへ」

TutorialはScene再起動ごとに再表示する最小実装とする。プレイヤー設定への永続保存やスキップ状態の記録は後続対応とする。

## アセット方針

- Scene、Prefab、Material、Shaderは追跡対象の `Assets/` 配下に置く。
- モデル、音源、生成したPNGなどの大きなバイナリアセットは既存方針どおり `Assets/Local/` 配下へ置き、Git管理しない。
- 生成するVFXテクスチャは、透明背景PNG・正方形・加算合成で白く使える素材を基本とする。色替え可能な白素材を優先し、用途ごとに増やし過ぎない。
- テクスチャを生成する場合は、必要な用途、解像度、透過の有無を先に定める。初期候補は `vfx_soft_circle.png`（256x256）、`vfx_spark.png`（256x256）、`vfx_trail.png`（512x64）、`vfx_ring.png`（512x512）。
- UI背景・フレーム・ラベルの画像も、既存HUDの雰囲気を参照して生成し直せる。ただし、画像生成とプロジェクトへの配置は明示的な指示を受けてから実施する。文字情報は画像へ焼き込まず、BitmapフォントとUIシェーダーで描画する。

## 二日間の実装順

### 1日目: ルールを成立させる

1. 出現矩形マーカー、`WaveDirector`、上限付き無限Wave、TimeUp／Result遷移を実装する。
2. GameHudを残り時間表示へ変更する。
3. `TimePickup` と敵死亡時ドロップを実装する。
4. Waveクリア回復、残敵表示、開始／クリア通知を接続する。
5. Debugビルドと、複数Waveを通した敵数・敵種比率・時間回復の手動確認を行う。

### 2日目: 手触りを整える

1. 敵撃破・回復取得・時間切れ間近のVFXを追加する。
2. Bloomの調整と、必要なら軽量な危機時ポスプロを追加する。
3. 使用可能な音源を接続し、追加SEを配置する。
4. チュートリアルを追加し、Wave構成と回復量を調整する。
5. Debugビルド、文字コード検査、手動通し確認を行う。

## 受け入れ確認

- 新規ゲーム開始時に60秒から時間が減る。
- 敵をすべて倒すと、Wave番号が進み、次Waveが開始され、時間が回復する。
- 敵を倒すと回復アイテムが出現し、取得すると時間が回復する。
- 時間が0秒になると、以後の操作・Wave進行が停止してResultへ進む。
- Waveをクリアすると、設定式に従った次Waveの敵が出現する。
- 敵の出現位置が4つのFieldマーカーで囲んだXZ矩形の内側に収まる。
- 敵撃破、回復取得、危機状態の少なくとも各1種類に視覚的フィードバックがある。
- チュートリアルの4項目が初回の流れに沿って表示される。
